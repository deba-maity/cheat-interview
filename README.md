# Stealth Assistant

An Electron desktop meeting and coding assistant with speech transcription, screen understanding, and provider failover. Windows is the primary target. The browser interface runs inside Electron because audio loopback, shortcuts, capture protection, and encrypted settings need desktop APIs.

## Run

Requires Node.js 22.12 or later; Node.js 24 is supported and was used for validation.

```powershell
npm install
npm start
```

The app starts without API keys. Open **Settings**, enter keys from your own accounts, and save. Use **Check connection** to test saved credentials. It sends a small request and may incur your provider's normal API charge. New credentials cannot be generated by the app.

- **Groq**: text answers and speech transcription. [Create a key](https://console.groq.com/keys).
- **OpenAI**: text, vision, and speech transcription. [Create a key](https://platform.openai.com/api-keys).
- **Gemini**: text and vision. [Create a key](https://aistudio.google.com/api-keys).
- **OpenRouter**: text and vision through its routing API. [Create a key](https://openrouter.ai/settings/keys).

Groq alone supports listening and screen questions through OCR. Add Gemini, OpenAI, or OpenRouter for direct image understanding. Add both Groq and OpenAI for transcription failover.

Keys saved in Settings are encrypted with Electron `safeStorage` in the current OS user's app-data directory. They are never returned to the renderer after saving. Blank key fields preserve existing credentials; **Clear saved keys** explicitly removes a provider's keys, including overriding an environment key. Multiple keys can be comma-separated. On systems without encrypted storage, use a local `.env` file instead.

For development configuration, copy `.env.example` to `.env` and fill in real keys locally. Restart after editing it. Settings override the corresponding environment values. Neither `.env` nor saved credentials are included in the installer.

## Listen and answer

1. Choose **Microphone**, **Meeting audio**, or **Both**. Meeting audio captures the Windows playback mix, including voices played through headphones; it includes other applications playing audio too.
2. Select a microphone when using Microphone or Both.
3. Press **Listen** / **Ctrl+L**. The input meter should move when someone speaks.
4. Pause after the question. A speech segment ends after approximately 1.2 seconds of silence and is transcribed.
5. With **Auto-answer questions** enabled, question-like utterances trigger an answer. This uses a local text heuristic, so **Answer this** remains available for missed questions. Switch auto-answer off for manual control.
6. Enable **Include screen** to combine spoken questions with the selected display. It also applies to **Answer this** on a transcript card.

Each clip is capped at 28 seconds and encoded as its own complete WebM/Opus recording. Silent clips are discarded. Only two clips can queue; if processing falls behind, listening pauses with a clear message. Audio stays in memory and is sent only to the configured transcription provider. Recent transcript context and conversation history stay in memory, bounded to the current session. **Clear conversation** clears them.

**Both** falls back to whichever source is available and displays a notice. Meeting-audio-only mode reports failure rather than silently using a different input. Hiding/minimizing the window stops capture. Source changes take effect when listening restarts.

If the microphone is denied, enable desktop microphone access in Windows **Settings → Privacy & security → Microphone**. If the input meter remains flat, check the device, Windows input/output levels, and whether the meeting is actually playing sound. System audio availability varies by operating system and audio driver; live meeting playback should be verified on the target computer.

## Screen questions and coding

Choose the display containing the question. Click **Read screen** / **Ctrl+I** to capture it and answer the typed prompt, or the default screen prompt. Vision-capable providers receive the screenshot; if vision is unavailable or fails, local Tesseract OCR extracts the text and a text provider answers it. Screenshots are processed in memory rather than written to temporary files. OCR uses the bundled English model and preserves line breaks.

Choose **Coding tutor** and your language for an approach, code, complexity, and edge cases. Code blocks scroll horizontally and have a separate copy button. Follow-up questions retain recent answers and transcripts. Answers display their provider, model, source (vision/OCR), and fallback diagnostics. Output-limit truncation is indicated.

## Fallback behavior

Default provider order: **Groq → Gemini → OpenAI → OpenRouter**, skipping providers without keys or a model for the requested capability. Model IDs, endpoints, and order are editable in Settings or `.env`.

- An unavailable model advances to the next model.
- A rejected, exhausted, or rate-limited key advances to another key/provider, with a short cooldown.
- Transport failures and server errors get one bounded retry before moving on.
- Empty/invalid responses also trigger fallback.
- Defaults: 18-second attempt timeout, 90-second task budget, maximum 12 attempts. Vision has a 30-second budget before OCR fallback; OCR and the subsequent text answer are separate stages.
- **Cancel** / **Escape** aborts pending network requests and invalidates queued clips. OCR checks cancellation before and after recognition; a running recognition can take a moment to finish.
- **Check connection** validates text connectivity using saved settings. Provider availability, account credits, and model access still depend on your accounts.

Groq uses `whisper-large-v3-turbo` / `whisper-large-v3`; OpenAI uses `gpt-4o-mini-transcribe` / `whisper-1`. Each receives its own provider's key and endpoint. See the [Groq speech documentation](https://console.groq.com/docs/speech-to-text) and [official OpenAI speech documentation](https://developers.openai.com/api/docs/guides/speech-to-text). Gemini uses its [OpenAI-compatible endpoint](https://ai.google.dev/gemini-api/docs/openai), and OpenRouter uses its [own routing endpoint](https://openrouter.ai/docs/quickstart). Model catalogues change; edit the fallback lists as needed.

## Window and shortcuts

| Shortcut | Action |
| --- | --- |
| Ctrl+L | Start/stop listening |
| Ctrl+I | Read selected screen |
| Ctrl+Enter | Move to the next corner of the current display |
| Ctrl+D | Light/dark theme |
| Ctrl+Shift+H | Show/hide |
| Ctrl+Shift+Q | Quit |
| Enter / Shift+Enter | Ask / new line |
| Escape | Cancel pending work |

The window is draggable, resizable, always on top, and excluded from the taskbar. Use its tray icon to restore it. Shortcut registration conflicts are reported; buttons remain usable.

Capture exclusion uses Electron `setContentProtection(true)`, preserving the original Windows display-affinity behavior. Supported Windows capture APIs exclude the window, but this is not a guarantee for every screen-sharing application or capture method. Verify the actual sharing application before relying on it. See [Electron's content-protection documentation](https://www.electronjs.org/docs/latest/api/browser-window#winsetcontentprotectionenable).

The old native overlay remains in `overlay.cpp` for reference. It is optional, no longer required to install or run; its include paths are now relative. `npm run rebuild:native` additionally needs a Windows C++ build toolchain.

## Build and validation

```powershell
npm test                  # provider, recording lifecycle, encryption, local API tests
npm run test:ui           # hidden Electron; synthetic mic; mocked APIs; real OCR
npm run test:ocr          # real offline OCR against the test fixture
npm run build            # Windows installer and unpacked app
npm run test:package      # package contents, no bundled secrets, packaged OCR runtime
```

The UI test uses an isolated OS temporary profile, synthetic microphone data, and fake API credentials. It does not call paid APIs or use your real microphone. The screen test uses a known coding-question fixture. Its screenshot is written to ignored `test-artifacts/`.

The build contains every renderer/preload/provider file, a generated icon, the OCR model, and unpacked OCR dependencies for worker compatibility. The legacy mandatory C++ installation step and bundled `.env` were removed. Dependencies were updated to Electron 44.7.0 and electron-builder 26.15.3; `@electron/get` is overridden to 5.1.x to avoid the builder's vulnerable older downloader chain.

Local validation passed: 33 Node tests; Electron speech → transcription → contextual answer; vision and real OCR fallback; cancellation; encrypted settings; screen-protection flag; offline and packaged OCR; Windows packaging. API responses were mocked because no real provider credentials were supplied. Physical microphones, live meeting playback, and real screen-sharing behavior need validation on your target setup.

## Optional local API

The desktop app does not need `server.js`. For local development, set `LOCAL_API_TOKEN` in `.env`, run `npm run server`, and send authorized JSON POSTs to `http://127.0.0.1:3001/api/ask` with `Authorization: Bearer <LOCAL_API_TOKEN>`. It reuses the provider/fallback service, binds to loopback, limits request size, and does not enable unrestricted CORS.
